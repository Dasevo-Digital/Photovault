# Photo Vault 1.10.3

Die Ergebnisse der Prüfrunde nach 1.10.2: Das Entwickeln braucht auf
Linux und Windows deutlich weniger Speicher, und die Karte merkt sich,
wie du sie eingestellt hast.

**Die Datenbank wandert von Fassung 48 auf 49.** Die Migration läuft
beim ersten Start von selbst und dauert nicht spürbar – es kommt eine
einzelne Spalte für die gemerkte Kartenansicht dazu.

## Entwickeln: jedes Bild wurde zweimal ausgepackt

Auf Linux und Windows rechnet beim Entwickeln ein eigener Weg, nicht
Core Image. Dieser Weg packte das Ausgangsfoto **in voller Grösse** aus,
las daraus Breite und Höhe ab und packte es dann ein zweites Mal aus –
diesmal verkleinert.

Der erste Durchgang diente also allein dazu, zwei Zahlen zu erfahren,
die im Dateikopf stehen. An einem 24-Megapixel-Foto gemessen:

| | Dauer | Arbeitsspeicher |
|---|---|---|
| ganz auspacken, um nachzumessen | 348 ms | 96 MB |
| Kopfdaten lesen | 3 ms | 0 MB |
| was danach wirklich gebraucht wird | | 6,8 MB |

Ausgepackt wird jetzt **einmal**, gleich in der richtigen Grösse. Das
wirkt bei jeder Vorschau und bei jedem Export – und je grösser das Foto,
desto deutlicher.

macOS war davon nicht betroffen.

## Die Karte merkt sich deine Einstellung

Die Wahl zwischen heller Karte, dunkler Karte, Topografie und Globus lag
bisher nur so lange vor, wie die Kartenansicht offen war. Wer die
Topografiekarte einstellte und zwischendurch etwas anderes ansah, fand
beim nächsten Öffnen wieder die dunkle Karte vor.

Jetzt bleibt die Wahl stehen – auch über einen Neustart hinweg.

## Zwei stille Stellen

**Abgebrochenes Aufräumen wird jetzt gemeldet.** Beim Sichern entsteht
ein Zwischenlager, in dem die Dateien **unverschlüsselt** liegen, bis
sie verschlüsselt am Ziel ankommen. Danach wird es gelöscht. Schlug das
Löschen fehl, geschah das lautlos: Der Klartext blieb liegen, ohne dass
es irgendwo stand. Die Sicherung scheitert deswegen weiterhin nicht –
aber der Fehlschlag steht jetzt im Protokoll.

**Zwei Bilddekoder gaben ihren Speicher nicht zurück.** Kein sichtbarer
Fehler, aber gehaltener Speicher, der auf den Aufräumer wartete.

## Was geprüft wurde und in Ordnung war

Damit es nicht wie eine Lücke aussieht, wenn dazu nichts steht:

- Die zur Anzeige entschlüsselten Dateien liegen auf **keiner**
  ausgelieferten Plattform in einem gemeinsamen Ablageort – unter macOS
  im abgeschotteten Bereich der App, unter Linux im eigenen Bereich des
  Flatpaks, beide nur für dich lesbar.
- Die Farbkontraste der dunklen Oberfläche liegen zwischen 5,9:1 und
  14,3:1 und damit durchgehend über der Schwelle von 4,5:1 – auch die
  kleinen grauen Beschriftungen.
- Keine Zugangsdaten im Protokoll, keine Shell-Aufrufe, keine
  Datenbankabfrage, in die Eingaben ungeprüft eingesetzt werden.

## Einspielen

**Linux**

```
flatpak install --user PhotoVault-1.10.3-x86_64.flatpak
flatpak run com.example.PhotoVault
```

**macOS** – Archiv auspacken, `Photo Vault.app` an den gewünschten Ort
legen. Mindestens macOS 14.0.

**Windows** – `PhotoVault-1.10.3-windows-x64.zip` auspacken und
`photo_vault.exe` starten.

## Hinweis zur Signatur

Weder die macOS- noch die Windows-Fassung ist mit einem gekauften
Zertifikat signiert. Unter macOS meldet sich Gatekeeper – über
**Rechtsklick → Öffnen** startet die App trotzdem. Unter Windows meldet
sich SmartScreen; über **Weitere Informationen → Trotzdem ausführen**
startet sie.
